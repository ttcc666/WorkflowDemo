## 补充修复：从审批详情返回监控时的 404

用户反馈后，2026-11-05 上午复现了首轮巡检遗漏的返回场景。点击监控列表中的审批，再点击详情“返回”，页面已回到监控，但会额外发出 `/api/approval/instances/undefined` 和 `/api/approval/instances/undefined/my-task`，均返回 404。

根因是离开详情时，Vue Router 先清除全局路由的 `params.id`，详情组件随后才卸载；详情查询的同步监听器在此间触发了一次无效资源查询。`features/approval/useApprovalDetail.ts` 现在允许实例 ID 暂时为空，并在实例、定义与待办三个查询入口检查 ID；原查询仍由现有加载器取消，不请求 `undefined`，有效 ID 的错误处理保持不变。没有修改后端、数据库或公共 HTTP 契约。

新增回归测试现位于 `web/packages/approval-ui/tests/features/approval/useApprovalDetail.test.ts`（目录整理前位于 `src/` 下）：

- `返回列表移除实例参数后不请求 undefined，并能再次加载有效实例`。
- `离开时取消尚未完成的待办查询，迟到错误不在列表弹出`。
- `有效实例查询真正失败时仍显示错误`。

前两个用例先在旧实现上失败，再经修正通过。再次运行 Frontend 门禁成功：UI 239、Demo 6、边界 7 个测试通过，类型检查及构建通过。日志：`output/playwright/ui-review-20261104/monitor-return-frontend.log`。本次没有重跑打包浏览器套件，前文 7 个打包用例的结果对应此前巡检版本。

Playwright 实测已驳回报销单的详情“返回”按钮，以及已通过证书、运行中测试申请的浏览器返回，均正常回到监控，没有新增无效 ID 请求，控制台 0 errors / 0 warnings。证据：`monitor-return-404-before.png`、`monitor-return-after.png`、`monitor-return-requests.log`（该请求日志同时保留修正前后的记录，修正前的 404 不应误认成修正后新增请求）。
