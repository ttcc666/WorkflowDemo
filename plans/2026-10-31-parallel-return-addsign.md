# 并行分支、驳回到指定节点、加签

## 目标

1. **并行分支**：新节点类型 `Parallel`（分叉，所有出线同时激活）与 `Join`（合并，等待全部分支到达后继续）。
2. **驳回到指定节点（退回）**：驳回时可选择“结束流程”或“退回到已经过的某个审批节点 / 发起人”。退回发起人后，发起人可修改表单重新提交或撤回。
3. **加签**：前加签（先请他人审，再回到自己）、后加签（自己同意后还需他人审）、并加签（与自己同时审）。加签的人必须同意，节点才能通过。

非目标：条件并行（包含网关）、跨并行块的任意跳转、会签比例通过、减签。

## 关键设计

### 结构化并行块
- 每个 `Parallel` 必须恰好对应一个 `Join`；分支内可嵌套条件与并行块，但不能跳出本块或在块内到达结束节点。
- 发布时静态分析每个节点所属的并行块栈（`FlowStructure`），校验结构；运行时据此判断退回目标是否合法、退出哪些并行块。
- 运行时状态：实例 `StateJson` 记录每个合并节点的 `expected / arrived` 计数；`CurrentNodeId` 改为当前所有活动节点（逗号分隔）。

### 退回
- 可退回目标：发起人（Start）+ 本实例已审批通过、且在图上位于当前节点上游、所在并行块是当前节点所在块的外层（或同层）的审批节点。
- 退回时：当前节点所有未完成任务取消；若目标在当前并行块之外，则取消整个块内的未完成任务并清除其合并计数；同块内退回不影响兄弟分支。
- 实例 `Round` 递增，新任务记录 `Round`，前端流程图按每个节点最新一轮的任务判断状态。
- 退回发起人：生成 `Resubmit` 任务给发起人；重新提交可携带新表单数据，从开始节点后重新流转；发起人此时可撤回。
- 节点选项 `allowReturn`（默认 true）。

### 加签
- 任务新增 `Kind`（Approval / Resubmit / AddSignBefore / AddSignAfter / AddSignParallel）、`ParentTaskId`。
- 前加签：原任务转为 `Suspended`，全部加签人同意后恢复为 `Pending`。
- 后加签：原任务同意，同时生成加签任务。
- 并加签：原任务保持待处理，同时生成加签任务。
- 节点通过 = 原审批方式（或签 / 会签 / 依次）在主任务上满足 **且** 不存在未完成的后加签 / 并加签任务。节点通过时其余未完成任务全部取消。
- 节点选项 `allowAddSign`（默认 true）。

## 兼容性
- 新增字段均有默认值，旧流程定义无需修改；旧的进行中实例（无 `StateJson`）按单路径处理。
- 表结构变化：`ApprovalInstances` 新增 `StateJson`、`Round`，`CurrentNodeId` 长度 100 → 500；`ApprovalTasks` 新增 `Kind`、`ParentTaskId`、`Round`。演示库需删除重建，正式项目需迁移。
- `RejectAsync` 新增可选参数 `targetNodeId`，不传时行为不变。

## 验证
- 后端：并行汇合、嵌套、结构校验；退回到上游 / 块内 / 块外 / 发起人并重新提交；三种加签与或签 / 会签 / 依次组合。
- 前端：flowModel 并行节点转换、按轮次计算运行状态；浏览器端到端。

## 风险
- 引擎推进逻辑由单路径改为多路径递归，回归风险 → 保留并扩充原有 58 个测试。
- 退回后节点重复激活，通知与超时会再次触发（符合预期，文档说明）。
