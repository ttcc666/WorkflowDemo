# 多租户数据访问安全加固

基线：origin/main = de663808f9fa6d66649512a8d3e45a62ced26b77。初始实施要求保留本地修改供审查；2026-11-10 用户已另行授权提交、推送及 GitHub CLI 验证。不创建 PR。

## 范围与不变量

- 保留宿主拥有身份、目录、权限、生命周期的边界，复用 UseApproval 与 ConfigureApprovalPartition。
- 分区 EF Context 默认拒绝原生 SQL、移除过滤器、分区字段批量修改；普通业务字段批量操作保持过滤，非分区行为不变。
- 对已跟踪写入统一验证分区来源、不可变性和数据库写入条件；Context 固定范围，池化必须 fail closed。
- 同步、异步、编译查询、组合查询一致；失败操作不得污染另一个租户的数据。
- 迁移走 EF 的迁移入口；不提供任意 SQL 的运行时豁免。
- EF 拦截器不是数据库权限系统：直接 ADO.NET、独立连接和持有数据库凭证的宿主代码必须单独验证并如实报告；不能以 SQL 字符串分析或不透明连接包装宣称数据库强隔离。

1. 核对实际主线代码、测试平台、持久化与作用域调用点。

4. 补充模型、作用域恢复、身份与后台行为测试；数据库矩阵复用相同攻击场景。
5. 验证针对性测试、完整 verify；尝试三服务数据库脚本并记录实际环境结果。
6. 检查最新 CI 的 SHA 与结果，明确其不包含本地未提交修改。
7. 交付问题、修改、测试、契约/迁移说明与数据库级剩余边界报告。

## 验证与回滚

- 每个拒绝测试随后以 Alpha/Bravo 新 Context 查询并核对存储结果。
- 先跑失败复现，再修复；完整门禁保留日志，不削弱断言。
- 数据库专项仅使用脚本所有的 approval_test_* 资源，不重置用户库。
- 不改变审批状态机；若修改模型/API，同步消费者和契约并运行 model drift 检查。
- 回滚以本次本地 diff 为单位，人工审阅后决定；不执行 reset/clean 或数据库清理。
