# Action 安全边界

宿主决定可用 Handler、HTTP 目标、SQL 查询和通知渠道。配置动作、发布、预演、审计和重试分别沿用现有能力检查。实例公开定义剥离动作步骤，实例审计详情要求 `approval.instance.read-sensitive`。普通接口没有写入输出变量的入口。

## JavaScript

`AddCalculationActions()` 显式启用 Jint 与 Mapping。每次计算创建独立 Jint Engine，输入为 JSON 快照。禁止 CLR、动态字符串编译和宿主对象注入。脚本长度、输入、执行时限、语句、内存、递归、数组、正则和结果均受预算约束。脚本文本保持原样，变量只通过 `context` 传入。Jint 在审批进程内执行，适用于受信任的流程设计人员。若宿主需要面向不受信任租户开放脚本，应为解释器配置独立进程及操作系统资源限制。

## HTTP

宿主注册精确 HTTPS URL 和允许的方法。默认端口为 443。只有宿主声明为只读的 GET 可以在事务中发起。连接回调检查 DNS 返回的所有地址，直接连接已检查的 IP 并保留原有 TLS 主机名验证。重定向、代理和 Cookie 关闭。目标地址和方法的指纹绑定到入队记录，宿主修改别名指向后须先恢复原绑定以重放旧请求。

需要 Bearer Token 的目标配置宿主凭证别名，实现 `IApprovalActionSecretProvider`。令牌在发出请求前解析。请求配置仅允许列入许可集合的头，自动写入异步幂等键。同步 GET 响应只读取受限 JSON。部署时应把 HTTP 客户端和数据库遥测视为敏感数据通道，并审核宿主导出的 URI 和 SQL 参数。

## SQL

每项查询绑定宿主提供的连接工厂、参数类型、行数和时限。配置人员只能使用数据源和查询标识。SQL 正文和连接信息由宿主管理，必须使用数据库只读权限并隔离审批主连接。参数通过 `DbParameter` 绑定。返回值只支持标量列，行数、列数、文本长度和 JSON 大小受限。

SQLite 使用标量读取获取文本，随后验证字段长度。SQLite 宿主应在注册的查询中限制大型文本投影的长度，避免驱动先将超大值读入内存。

## 配置与日志

Outbox 保存动作输入快照，存储访问权限应与审批数据一致。HTTP 凭证不会写入快照。自定义 Handler、脚本和 Mapping 的作者只应保存后续步骤需要的业务字段。审计记录保存步骤标识、状态、耗时和输出大小，外部投递错误只显示安全错误类别和 HTTP 状态。
