# React 全页面逐页检查与优化

用户要求仔细检查每个页面并继续优化；本轮直接实施并验收。

## 范围与不变量

检查 9 个审批路由、注册证页、3 个设计器主面板（流程、表单、发起设置）、Action 配置与模拟、版本／治理／审计、通知及业务弹窗。每页检查桌面 1280px 和手机 390px；设计器同时检查画布、属性面板、工具栏和弹窗。

保留 shadcn/ui Radix Nova、现有共享 Schema、后端、Vue 稳定前端与全部业务动作。节点仍为 220×72；拖拽、连线、分支、撤销重做、插入、布局、Action、模拟均保留。隐藏字段、人员目录权限、稳定操作键、未知结果恢复、表单草稿、只读已发布版本和导航未保存保护不变。

## 实施步骤

1. 记录每页实际问题与截图，在隔离 SQLite 宿主中生成验证数据；不修改用户开发数据库。
2. 统一页面标题与说明、Card 间距、筛选工具栏、DataTable 层级与移动排列、Metrics 真实数据显示。
3. 对发起入口、流程定义、设计器、监控／诊断和注册证作各自必要的结构调整，不堆砌同一套看板。
4. 新增行为只限必要的列表搜索、分类和展示；针对这些行为和布局增加明确回归用例。
5. 运行前端门禁、完整源码与 tgz 消费者浏览器验收；逐页保存桌面／手机截图并复核。

## 验证与回退

优先使用 `eng/verify.ps1 -Scope Frontend -SkipRestore`、`pnpm test:e2e:react`、`pnpm verify:react-package`、`pnpm test:e2e:packed`。按真实交互验证，不能把 build 当 tests。无后端改动时不运行服务数据库专项。

修改前保留本轮涉及文件的快照；回退只恢复本次 UI 差异，不重置此前 React／shadcn 工作，不提交／推送，不删除任何开发数据。
